# 架构与生命周期

核对入口：[package.json](../package.json)、[服务](../src/server.js)、[引擎](../src/engine.js)、[前端](../ui/app.js)。业务约束见 [首期规格](../specs/model-quality-v1/spec.md)。

## 启动与页面

1. Magpie 按 `package.json` 的 `main` 加载 [插件入口](../src/plugin.js)。插件创建受管服务，返回空供应商钩子；它是页面插件，不提供新模型供应商。
2. [受管服务](../src/managed.js) 探测指定端口的 `/_check/health`。应用、版本和配置指纹一致时附着已有服务，否则尝试启动；不兼容占用会报错。
3. [启动页](../page/index.html) 加载 Magpie 官方 bridge。[boot.js](../page/boot.js) 等待握手和选项，优先使用 `magpie.service`；本机环境才回退到回环服务地址。随后跳转到实际界面。
4. [实际界面](../ui/index.html) 由服务返回，包含短期 API 令牌。API 路径相对于文档地址解析，以兼容 Magpie web 的代理路径。
5. 独立运行由 [CLI](../src/cli.js) 直接启动同一个服务，不经过宿主 bridge。

`page/` 是启动外壳，`ui/` 是业务页面；修改两 Tab、记录列表或详情时，应进入 `ui/`。

## 测试请求

配置自动保存或立即测试 → 服务接口 → 引擎排队 → 网关调用 → 自动判定 → SQLite 保存 → 页面重新读取有效结果。

- [网关模块](../src/gateway.js) 读取模型目录、排除路由组及已知非文本模型；从两种目录字段中整理支持的推理强度。
- 调用只提交配置快照中的模型、题目、token 上限及可选推理强度。标准答案保存在本地判定定义中，不放进请求内容。
- [测试注册](../src/tests/index.js) 当前只有 `milk`。[原题](../src/tests/milk-prompt.js) 与 [判定](../src/tests/milk.js) 分开维护，第三方来源见 [许可证说明](../THIRD_PARTY_NOTICES.md)。
- 引擎按 testId 选择 milk 或独立的 Fingerprint 执行器。Fingerprint 复用 vendored SDK，通过 Gateway.sample 请求；ReferenceBank 管理快照下载、校验及每日更新。

## 调度与进程

[引擎](../src/engine.js) 的内存映射对模型和类型复合键去重、同模型串行，队列统一控制并发；配置和 `nextAt` 持久化。定时轮询查找已到期且没有未完成任务的模型，入队后推进下次计划；任务完成时也会推进已经过期的计划，避免补跑风暴。

关闭自动测试只更新计划；移除模型通过 AbortController 取消任务。排队和执行中的记录均受这一规则控制。请求参数在入队时快照，后续配置修改不会改变该任务。

服务绑定回环端口后，在 SQLite 中取得数据目录的拥有者，再创建引擎并修复遗留记录。拥有者表记录进程及令牌；不同端口不能对同一库重复调度。附着宿主定期重试接管，原拥有者退出后可恢复监听。

`close()` 停止引擎并释放拥有者。异常退出后的 `queued/running` 记录，在下一次拥有者启动时修复为 `interrupted`。本地进程身份和回环地址是当前实现边界，不是跨机器分布式租约。

## 历史、矫正与清空

[Store](../src/store.js) 汇总当前有效结果，人工结果优先；调用状态、自动判断和原始回答独立保留。矫正／恢复追加日志，历史摘要和详情由同一来源计算结果。

热力图按配置时区把记录归入日期和六小时时段；未完成任务单独计数。清空只删除已结束记录并级联删除日志，未完成记录在完成后继续出现。移除配置保留历史模型，用户仍可切换查看。

## 宿主主题与提示

[theme.js](../ui/theme.js) 接受宿主握手和主题事件，并写入主题属性及 `--magpie-*` 变量；独立页面使用系统主题。样式优先使用宿主背景和文字色，Tab 按钮透明，避免全局按钮白底露出色块。

正常连接没有状态徽标；失败提示由 `ui/app.js` 的通知区呈现，支持重试，页面令牌失效则提示重新加载。页面只读取自己的检测数据，不把“页面连接成功”当作模型可用证明。

历史模型选择器使用原生 Popover API 承载主题化 listbox，位于顶层以避免容器裁切；展开时按触发按钮与可用窗口空间定位。滚动主页面或调整窗口会收起列表。详情与添加模型弹层使用固定标题＋`.dialog-body` 滚动区；`html/body:has(dialog[open])` 锁定背景，正文 `overscroll-behavior:contain` 阻止滚动传递。关闭由原生 dialog 生命周期处理，Esc 与按钮关闭均自动解除背景锁定。重新打开后须在 `showModal()` 之后重置正文位置，隐藏时设置 scrollTop 不会可靠生效。

指纹接口和迁移见 [接口与数据](interfaces.md) 的指纹扩展；产品语义见 [指纹规格](../specs/fingerprint-monitoring/spec.md)。参考库更新计时器属于服务端，与页面是否可见无关。

## 界面优化（2026-11-16）

历史上下文工具栏集中模型、类型与操作；清空放原生 Popover 的更多菜单。热力图保持每模型横向位置，首次在窄窗口定位最新日期；按渲染内容签名避免轮询重建焦点节点。浮层支持悬停与聚焦；日期／时段表单提供替代选择。

指纹 Store 查询使用 CTE／窗口函数在完整历史上建立前一有效快照及前一完整评分关系，然后筛选变化并分页。本页分组只合并同日期、相同候选 ID、参考库与 SDK 的完整评分，变化边界不合并，默认关闭；分页数量始终按原始记录计数。

奶牛详情按结果、答案对比、完整回答、折叠矫正及参数／日志排列。矫正重绘保留展开状态；新开详情清空旧正文后再渲染。设置使用模型下的两条独立计划行；自动保存成功反馈短暂显示，错误持续并可重试。

## 指纹分布图

图表使用普通 HTML 轨道与按钮按真实时间百分比定位，无图表依赖。候选按 ID 分行，颜色由 ID 的稳定哈希选择，类别名称与形状提供非颜色编码。视图根据范围以绝对时间桶合并同候选、同评分形态的密集点，相邻桶在紧凑跨度内再合并，组内保留所有记录入口。30 天统计与图表范围分别展示。

渲染签名包括模型、范围、分钟与记录摘要；常规三秒轮询不重建同样内容。分钟变化更新轴域；重绘恢复横向滚动与相同记录焦点。点组使用固定标题、独立正文的 dialog，打开单轮详情前关闭组弹层。

## 共享模型设置（2026-11-19，0.5.0）

设置现为每模型单卡，测试项复选框与定期总开关分离。Engine.saveModel 原子同步类型配置，model-config.js 汇总模型视图并选择旧参数来源。引擎启动时直接转换所有旧配置，优先唯一启用项，否则采用奶牛，不增加迁移界面。

enqueueSelected 先检查整个模型无任务，再事务创建两项记录，提交后发布到内存队列。入队时统一推进计划；tick 对共享模型整组调度，busy 时跳过；最后一个模型任务完成后推进过期 nextAt。类型执行器、串行和全局两任务上限不变。修改／暂停只影响后续快照，移除继续取消两项。
