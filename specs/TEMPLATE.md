# 新能力模板

复制以下章节到 `specs/<feature>/` 的四个文件中。删除不适用内容；保留关键未决问题和真实验收状态。

## spec.md

```md
# <能力名称>

状态：草案
来源：<用户要求、issue 或既有规格>

## 目标与边界

<用户要完成什么；本次交付和以后再做什么。>

## 需求

| ID | 可观察行为 | 失败或边界场景 |
| --- | --- | --- |
| <PREFIX>-001 | <行为> | <边界> |

## 未决问题

<影响实施的决定；没有则写“无”。>
```

## plan.md

```md
# <能力名称> · 实施方案

## 方案

<代码拥有者、数据流、必要接口变化。>

## 兼容与历史

<配置、数据、规则版本如何处理；无变化时说明。>

## 验证

<关联需求 ID，选择自动检查和实际环境验收。>
```

## tasks.md

```md
# <能力名称> · 任务

- [ ] <需求 ID>：<可检查的实施产物>
- [ ] <需求 ID>：<验证与证据>
- [ ] 更新接口、知识库及规格索引中受影响的部分。
```

## contracts/acceptance.md

```md
# <能力名称> · 验收

| 场景 | 需求 ID | 操作与预期 | 证据／检查入口 | 结果 |
| --- | --- | --- | --- | --- |
| A-001 | <PREFIX>-001 | <具体场景> | <测试文件或实际记录> | 未执行 |

## 执行记录

<日期、实际命令／环境、结果；未运行时明确写出。>

## 待验收

<需要实际环境或用户验证的内容；自动测试结论的边界。>
```
